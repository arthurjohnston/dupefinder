D. AI Inference Layer (ai_helper.py) All LLM calls are routed through the ask_ai function in core/agents/ai_helper.py. This module implements a roundrobin, round-robin, fault-tolerant key-and-model rotation strategy designed to remain within the free-tier limits of the Gemini API (15 requests per minute per key).

a) Key collection.: _collect_keys() assembles an ordered, deduplicated list of API keys by reading first from settings.GEMINI_API_KEYS (a list populated at startup from environment variables GEMINI_API_KEY_1 through GEMINI_API_KEY_3), then from individual environment variables as a fallback.

b) Model pool.: Three Gemini models are tried in preference order: gemini-2.5-flash, gemini-2.5- flash-lite, and gemini-1.5-flash. The MODELS list makes it trivial to extend support to future releases.

The _next_combo() function scans all (key, model) pairs and skips any that were marked within the 65-second COOLDOWN window, automatically un-marking them once the cooldown has elapsed. The outer retry loop in ask_ai attempts up to |keys|×|models| combinations before giving up, inserting a 15-second 15- second sleep if a rotation pass finds every combination still cooling down.

Planner Agent planner_agent(topic, language) constructs a Gemini system instruction that fixes the output language and mandates exactly nine sections (Abstract through References). The user prompt requests a JSON object whose sections array entries each carry a title, a description, and a search_queries list of two to three English- language web-search strings. Because json_mode=True is set, the raw Gemini response is parsed immediately with json.loads() and returned as a Python dict to the pipeline orchestrator.

A LANGUAGE_NAMES mapping translates the ISO 639- 1 codes accepted by the UI (en, es, fr, . . . , ko) into full language names that are embedded in both the system instruction and the user prompt, ensuring that section titles and descriptions are produced in the requested language.

F. Search Agent search_agent(query) posts a single query to the Tavily Search API (https://api.tavily.com/search) with max_results=3 and a 10-second timeout. The API key is read from the TAVILY_API_KEY environment variable, with a development key as the fallback default. Each result object returned by Tavily includes title, url, and content fields; these are passed directly to the Analyst Agent as citation source material. Network errors are caught and logged, and an empty list is returned so that the pipeline can degrade gracefully rather than abort. G. VII. FUTURE ENHANCEMENTS While the Oretes Insight System successfully automates the core research synthesis pipeline, the evaluation phase identified several concrete architectural limitations and user-experience gaps that motivate the following planned improvements.

Asynchronous Pipeline Execution: The current run_pipeline function in views.py is fully synchronous, blocking the Django worker thread for the entire duration of report generation. Under concurrent load this exhausts the worker pool and prevents Peer Reviewed, Referred & Indexed Journal ISSN: 3068-272X www.ijdim.com Original Research Paper simultaneous users from generating reports. A future version will replace this with Django Channels or Celery task queues, decoupling generation from the HTTP request–response cycle and enabling true concurrent multi-user operation. Realtime Real-time progress would then be pushed to the client via WebSockets rather than polled from the /stage/ endpoint.

Persistent, Multi-Session State: All session data— research history, generated assets, and plagiarism records— is currently held in module-level Python dictionaries (_research_history, _assets, _plag_checks) that are lost on server restart and are not shared across worker pro- cesses. A future release will migrate this state to the existing SQLite database (or PostgreSQL for production deployments) using proper Django models, giving users durable access to their full report history across sessions and devices.

Fully Implemented Reviewer Agent: The "reviewer" entry in AGENT_STATE is currently set to "complete" im- mediately after the Analyst Agent returns, without performing an independent qualityassessment quality-assessment pass. A genuine Reviewer Agent will be introduced that evaluates each generated section against predefined thresholds for word count, citation density, and technical depth, and recursively resubmits failing sections to the Analyst Agent for refinement until all criteria are satisfied.

Live Academic Source Integration: The Search Agent currently queries the Tavily general web-search API, which does not guarantee peer-reviewed sources. Future versions will add direct integrations with arXiv, Semantic Scholar, and the IEEE Xplore API, enabling the system to retrieve and cite verified academic papers. This would replace synthesised BibTeX entries with real, verifiable references and improve the scholarly credibility of exported documents.

Multimodal Input Support: The Gemini models used in the inference layer (ai_helper.py) already support mul- timodal inputs natively. A planned enhancement will expose this capability through the frontend, allowing users to upload existing PDF papers, images of handwritten notes, or data tables that the Planner Agent can incorporate into the research outline and citation pool.

Advanced LaTeX Template Support: The generate_latex view currently produces only IEEEtran-class documents. Future iterations will extend the /api/latex/ endpoint to accept a template parameter, supporting additional document classes such as acmart (ACM), revtex4-2 (APS Physics), and elsarticle (Elsevier), making the system suitable for a wider range of publication venues.

Improved Image Generation Pipeline: Image generation currently relies on a three-tier fallback (Imagen 3 → Gem- ini 2.0 Flash → Pollinations.ai), with the third tier returning externally hosted URLs that may become unavailable. A future version will cache generated images as Base64 blobs in the database alongside their parent report, and will expose a dedicated asset library page so users can manage, reuse, and download visual assets independently of the report view. Automated Presentation Export: Building on the existing /api/latex/ and clipboard export pathways, a planned /api/slides/ endpoint will transform the completed ninesection report into a structured slide deck (PowerPoint or Beamer LATEX), mapping each section to a set of presentation slides with auto-extracted key points, section-level charts, and speaker notes derived from the full prose content.

Enhanced Plagiarism and Fact-Checking: The current /api/plagiarism/ endpoint uses an LLM to estimate originality, which is a heuristic rather than a definitive cross- reference crossreference check. A future module will integrate with external originality APIs (e.g., Copyleaks or iThenticate) to perform genuine database-backed plagiarism detection, and will add a separate fact-checking factchecking pass that crossreferences cross-references numerical claims and statistics against the retrieved source documents.

Per-User API Key Management: The runtime key- addition endpoint (/api/add-key/) currently appends keys to a settings list shared across all sessions. A future release will introduce proper user accounts with per-user Gemini API key vaults, usage-quota tracking, and key-health dashboards, separating individual key pools and enabling the system to scale to a multi-tenant production deployment.
