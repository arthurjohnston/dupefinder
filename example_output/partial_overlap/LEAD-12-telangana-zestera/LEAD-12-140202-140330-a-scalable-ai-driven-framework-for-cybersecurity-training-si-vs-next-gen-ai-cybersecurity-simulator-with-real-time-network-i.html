Proposed System The proposed system operates through a sequence of interconnected steps involving simulation, distributed processing, anomaly detection, and visualization. The proposed system integrates a network simulation layer with a MapReduce-based anomaly detection engine to provide a real-time monitoring dashboard as shown in figure. 1. Users simulate file transfers on a network (Port 3333), generating traffic data that is independently analysed by the Network Monitor (Port 4444). The core logic, simulated via MapReduce, classifies packets as normal or attack based on a size-based heuristic (e.g., MB), instantly updating internal counters. The results are immediately visualized on a JFreeChart Dashboard, offering trainees a direct, real-time understanding of how distributed processing and simple AI rules can detect and respond to network anomalies. Network Simulation and Data Generation: The process begins with the Main and Network classes providing a graphical user interface where a user configures a network with simulated users. The user then initiates a file transfer (upload or download) via the Network class, selecting a file size and a simulated user ID. This action triggers two key concurrent processes: the file transfer itself handled by the Server (Port 3333) and the generation of network traffic data representing the file size, which is sent to the monitoring component.
